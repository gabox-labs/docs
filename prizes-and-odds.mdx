Every machine has one immutable prize table with up to eight rows. The Gabox app creates a fixed four-row table whose top row is 10×. The program also accepts other valid tables with a top row up to 20×, so a machine created through the SDK may show different prizes.

| Field | Meaning |
| --- | --- |
| Multiplier | Packs named by that row. `10,000` basis points is 1×. The app's top row is 10×; the program limit is 20×. |
| Tickets | Equal chances assigned to the row. All rows total 65,536. |
| Amount | `floor(1,000,000 × multiplier_bps / 10,000)` tokens. |
| Chance | `tickets / 65,536`. |

MagicBlock VRF supplies randomness. Each pack gets a domain-separated SHA-256 derived 16-bit ticket from the VRF randomness, pool, sequence, and pack index. It selects one of 65,536 equal chances, without modulo bias. The program knows rows; Common, Rare, Epic, and Mythic are app labels.

## Expected payout

The app's table has four rows: Common 0.5126× (about 80%), Rare 2× (about 15%), Epic 3.5× (about 4%), and Mythic 10× (about 1%). The program rejects any table whose uncapped expected payout is above one pack. This is token accounting, not a promise of price, profit, or cash return.

## Caps and reservations

At purchase, Gabox snapshots the table and free vault inventory. The first pack's displayed top prize is capped at free inventory plus its own pack. A batch settles in order, and each later pack sees inventory after earlier packs. The buyer signs a floor for the first pack's displayed maximum.

A jackpot can be capped temporarily after large wins. New purchases and donations can rebuild free inventory. A cap cannot change the table or make a pending draw depend on a later deposit.

For example, the app's 10× row names 10,000,000 tokens, but on a new machine with no extra seed it can initially pay only 3,000,000. Its roughly 1% chance stays the same. Review the exact table and **payable** amounts shown for a machine before signing.
